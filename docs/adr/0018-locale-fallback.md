# ADR 0018: 閲覧用 API は ?locale で言語を受け取り、翻訳がなければ ja で返す

- **Date**: 2026-10-16
- **Status**: Accepted
- **Supplements**: [0002](0002-translation-tables.md)

## Context

[0002](0002-translation-tables.md) で、英訳しないデータは `ja` の行だけでもよいと決めた。このとき、英語で表示しようとしたデータに英訳がない場合に、API が何を返すかは決めていなかった。

## Decision

- 閲覧用 API は、クエリパラメーター `?locale=ja|en` で言語を受け取る。省略したら `ja` にする
- 指定した言語の翻訳がなければ、`ja` の翻訳を返す。`ja` もなければ、データがないものとして扱う
- レスポンスの `data.locale` に、実際に返した言語を入れる。フロントエンドはこれを見て、「英訳がない」などの表示ができる

翻訳を選ぶ処理は domain 層の `selectTranslation` にまとめ、各ユースケースから使う。

### 検討した選択肢

| 案 | 内容 | 採否 |
|----|------|------|
| A | 翻訳がなければ `ja` で返し、実際の言語を `locale` で示す | 採用 |
| B | 翻訳がなければ 404 を返す | 不採用(英訳していないデータが英語の画面に出なくなる) |
| C | 言語を `Accept-Language` ヘッダーで受け取る | 不採用(ブラウザの設定に左右され、画面で言語を切り替えにくい。URL で言語が分からず、キャッシュもしにくい) |

## Consequences

- 英訳がなくても、英語の画面に日本語で表示される
- 一覧を返す API では、項目ごとに `locale` が異なることがある
- 管理用 API は全言語の翻訳をまとめて扱うので、この ADR の対象外とする
