# ADR 0004: スキルは独立したマスタにし、案件・個人開発とは明示的な中間テーブルでつなぐ

- **Date**: 2026-10-15
- **Status**: Accepted

## Context

スキルは2か所で使う。

- スキル一覧: 「クラウド: AWS, Azure, GCP」のように、カテゴリごとに並べる
- 案件・個人開発の「環境」欄: その案件で使った技術を並べる

環境欄をテキストで書くと、同じ技術でも案件ごとに表記がばらつく。実際に職務経歴書の中でも `CosmosDB` / `Cosmos DB`、`VNet` / `Azure Virtual Network` のような揺れがある。

## Decision

### スキルは独立したマスタにする

`Skill` はどこにも依存しないマスタとして持つ。案件・個人開発の側から「この案件ではこれを使った」と参照する。

### 多対多は明示的な中間テーブルにする

`AssignmentSkill` と `ProjectSkill` を明示的な中間テーブルとして定義する。Prisma の暗黙の多対多は使わない。中間テーブルには、その案件内での表示順(`sortOrder`)を持たせる。

### 表記ゆれは運用で防ぐ

`Skill.name` は unique にする。大文字小文字や空白の違いによる重複は、DB では防がず運用で防ぐ。編集画面では、既存のスキルを検索して選べる UI(オートコンプリート)にする。

### 検討した選択肢

| 案 | 内容 | 採否 |
|----|------|------|
| A | 環境欄を案件ごとのテキストで持つ | 不採用(表記がばらつき、技術からの逆引きもできない) |
| B | Prisma の暗黙の多対多を使う | 不採用(表示順などの項目を後から足せない) |
| C | 正規化した `slug` や `citext` で表記ゆれを DB で防ぐ | 不採用(登録するのは自分だけなので、運用で十分) |

## Consequences

- 環境欄の表記がスキルマスタに揃う
- 「TypeScript を使った案件一覧」のような逆引きができる
- 使用中のスキルは削除できない(`onDelete: Restrict`)。先に案件・個人開発から外す必要がある
- `Vue.js(Vue3)` のようなバージョンの書き分けはできない。必要になったら中間テーブルに項目を足す
