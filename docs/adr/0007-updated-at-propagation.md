# ADR 0007: 翻訳や中間テーブルを更新したときも親の updatedAt を更新する

- **Date**: 2026-10-15
- **Status**: Accepted
- **Supplements**: [0002](0002-translation-tables.md)

## Context

Prisma の `@updatedAt` は、その行が更新されたときにだけ時刻が変わる。

自己PR を書き換えた場合、更新されるのは `ProfileTranslation` の行である。`Profile.updatedAt` は変わらない。そのため、サイトに「最終更新日」を出すと古い日付が表示される。

サイトでは、最終更新日を実際の更新に合わせて表示したい。

## Decision

親の `updatedAt` は「その項目の最終更新日時」として扱う。

翻訳テーブルや中間テーブルだけを更新するときも、同じトランザクションで親に `updatedAt: new Date()` を明示して更新する。管理用 API では、親の update に子の更新を含める形で書く。

```ts
await prisma.profile.update({
  where: { id: 1 },
  data: {
    updatedAt: new Date(),
    translations: { upsert: { /* ... */ } },
  },
})
```

翻訳テーブルを持つモデルすべてに同じルールを適用する。

### 更新処理はリポジトリ層の集約単位の保存関数に閉じる

この処理はアプリ層に置く。Prisma のモデルはデータの形を表すもので、振る舞いを持つドメインオブジェクトではないためである。

親とその翻訳・中間テーブルをひとつの集約として扱い、親を集約ルートとする(例: `Profile` と `ProfileTranslation`)。子は親を通してしか更新しない。リポジトリ層には `saveProfile(profile)` のような集約単位の保存関数だけを用意し、親の `updatedAt` の更新はその関数の中に書く。こうすると、更新処理が集約ごとに1か所にまとまる。

### 検討した選択肢

| 案 | 内容 | 採否 |
|----|------|------|
| A | 管理用 API で親の `updatedAt` を明示して更新する | 採用 |
| B | DB のトリガーで、子の更新時に親の `updated_at` を自動で更新する | 不採用(ロジックが schema にもコードにも現れず、追いにくい) |
| C | 表示時に、親と子の `updatedAt` の最大値を計算する | 不採用(取得のたびに計算が要る) |

## Consequences

- 子を直接更新するコードを書くと、親の `updatedAt` が更新されず最終更新日がずれる。子の更新は集約単位の保存関数だけで行う
- 更新漏れが問題になったら、案 B のトリガーを新しい ADR で検討する
