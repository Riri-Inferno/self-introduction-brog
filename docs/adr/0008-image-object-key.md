# ADR 0008: 画像はストレージのオブジェクトキーで持ち、URL は API で組み立てる

- **Date**: 2026-10-15
- **Status**: Accepted

## Context

プロフィールのアイコンや個人開発のサムネイルなど、画像は S3 などのストレージサービスに置く。

当初は署名付き URL を DB に保存することを考えた。しかし、S3 の署名付き URL には有効期限がある。最長でも7日で、作成した認証情報によってはもっと短く切れる。DB に保存すると、期限が切れた時点で画像が表示されなくなる。

## Decision

画像はストレージ上のオブジェクトキー(例: `projects/gcp-vector-search.png`)を `String?` で持つ。カラム名は `xxxKey` とする(`Profile.avatarKey`、`Project.imageKey`)。

API がレスポンスを返すときに、キーから URL を組み立てる。

- 公開画像なら CloudFront などの URL にする
- 署名付き URL が必要なら、API で毎回発行する

### 検討した選択肢

| 案 | 内容 | 採否 |
|----|------|------|
| A | オブジェクトキーを持ち、URL は API で組み立てる | 採用 |
| B | 署名付き URL を DB に保存する | 不採用(期限が切れると表示されなくなる) |
| C | 公開 URL をそのまま DB に保存する | 不採用(配信元を変えたときに全行の書き換えが要る) |

## Consequences

- 配信元(S3 直、CloudFront など)を変えても DB を書き換えなくてよい
- API にキーから URL を組み立てる処理が要る
